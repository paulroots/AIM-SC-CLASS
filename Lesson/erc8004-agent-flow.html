Under the hood · ERC-8004 and a payment contract

The code behind each step

ERC-8004 defines three registries: Identity (who is this agent, and where do I reach and pay it?), Reputation (what did past clients say?) and Validation (did an independent checker confirm the work?). It deliberately leaves payment out. The AgentEscrow below is our own example of how a payment contract can read those registries to decide when, and to whom, to pay.

Draft ERC · signatures may change
Status: ERC-8004 “Trustless Agents” is a Draft standard, created 2025-08-13 by authors from MetaMask, the Ethereum Foundation, Google and Coinbase. How this relates to DIDs

An agent ID works like a DID for software: a public, permanent identifier with a controller, a list of endpoints and a payment address. The registration file can even list a DID. The difference is the extra trust layer: reviews and independent checks, both on chain.

Limits to discuss

Anyone can register an agent and anyone can leave feedback, so the client must choose whose reviews count. Reputation stays with the agent ID when it is sold. A validator score is only as good as the validator.
