Part 2
Min 10 to 25

Reading a smart contract

We read Counter, a contract that stores one number, line by line. It is small, but it uses every idea you will meet in bigger contracts.

What I will do
  1. Show where the contract keeps its data.
  2. Show the three ways to change the number: increment, decrement, set.
  3. Show who is allowed to do what.
Watch for
  • The owner: only the deployer can set the number directly.
  • The event that announces every change.
  • Why the number refuses to go below zero.
Access control ABI Bytecode
Part 3
Min 25 to 40

Testing before we deploy

Once a contract is on a blockchain it cannot be edited. So we prove it works first.

What I will do
  1. Run eight automated tests against Counter.
  2. Pretend to be a stranger and try to break the owner rule.
  3. Open a full trace of a failed call, step by step.
  4. Show how much each function costs in gas.
Watch for
  • Tests that pass because the contract correctly refused.
  • Fuzzing: the computer tries hundreds of random values for us.
  • Writing data costs far more gas than doing maths.
On my screen
make test
forge test --gas-report
Gas Opcode and storage costs
Part 4
Min 40 to 55

A private blockchain on my laptop

Before going public, I deploy to a blockchain that lives only on my machine. Same rules, no cost, no audience.

What I will do
  1. Start a local blockchain with ten pre-funded accounts.
  2. Deploy Counter and get back its address.
  3. Open a web page for the contract and press Increment.
  4. Approve the transaction in MetaMask.
Watch for
  • A deploy is just a transaction, like any other.
  • Reading the number is free; changing it needs a signature.
  • The event log updating live after each click.
Deployment transaction Contract address Call vs transaction Nonce
Part 5
Min 55 to 75

Publishing to a public network

Now the same contract goes to Prismo Glassnet, a public test network. From this moment anyone in the world can read it.

What I will do
  1. Deploy Counter to Prismo Glassnet.
  2. Open it on the block explorer, the public record of the network.
  3. Verify the source code so anyone can read it.
Watch for
  • The transaction, its block, its gas used and its fee.
  • Before verification, the explorer shows only bytecode.
  • After verification, the real Solidity appears next to it.

Part 6
Min 75 to 90

Hello World, from zero to live

The whole journey in fifteen minutes: a brand-new contract that stores a greeting, written, tested and published while you watch.

What I will do
  1. Generate a new HelloWorld contract with one command.
  2. Write the greeting: "Hello, World!"
  3. Test it, then deploy it locally.
  4. Read the greeting back from the terminal.
  5. Change it to "Hello, AIM!" from the web page.
  6. Publish it to Prismo Glassnet and verify it.
Watch for
  • The same steps as Counter, start to finish.
  • The MessageChanged event when the greeting changes.
  • The final explorer link: open it and read the greeting yourself.
